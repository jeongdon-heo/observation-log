# 세상 돋보기 - 개발 과정 문서

## 개발 일지

### Day 1 (2월 11일) — 프로젝트 생성 및 핵심 기능 구현

#### 1단계: 프로젝트 초기 설정
- Create Next App으로 Next.js 14 + TypeScript + Tailwind CSS 프로젝트 생성
- Firebase 프로젝트 연동 (Authentication, Firestore, Storage)
- 기본 폴더 구조 설계

#### 2단계: 전체 기능 1차 구현
AI(Claude)에게 앱의 전체 기능을 설명하고 한 번에 구현을 요청했다.

**구현된 기능:**
- 회원가입 / 로그인 (교사, 학생 역할 분리)
- 교사: 대시보드, 미션 생성, 학급 초대 코드
- 학생: 반 참여(초대 코드), 미션 목록, 관찰 일지 작성
- 관찰 일지: 텍스트 + 사진(최대 5장) + 날씨 + 관찰 날짜
- AI 칭찬 댓글: Google Gemini로 학생 글에 즉시 피드백

**사용한 프롬프트 (요약):**
> "초등학교 자연 관찰 기록 웹 앱을 만들어줘. 교사가 미션을 만들면 학생이 관찰 일지를 작성하고, AI가 칭찬 댓글을 달아주는 앱이야."

**배운 점:**
- 한 번에 전체 앱을 요청하면 기본 구조가 빠르게 잡히지만, 세부 기능은 추가 작업이 필요하다.

**사용한 프롬프트 (요약):**

- 다수의 배포 에러를 순차적으로 해결:

| 에러 | 원인 | 해결 |
|------|------|------|
| ESLint 에러 | 미사용 변수/임포트 | 코드 정리 |
| API 라우트 빌드 에러 | 정적 빌드 시 API 호출 시도 | `force-dynamic` 추가 |

| 환경 변수 미적용 | NEXT_PUBLIC 변수가 빌드에 포함 안 됨 | .env.production 파일에 추가하여 커밋 |

**배운 점:**
- Vercel 배포 시 빌드 타임에 코드가 실행될 수 있어서, Firebase 같은 외부 서비스 초기화는 반드시 지연 초기화로 해야 한다.
- NEXT_PUBLIC 환경 변수는 빌드 시 번들에 포함되므로, Vercel 환경 변수가 아닌 .env.production에 넣어도 된다.

### Day 4~5 (2월 15일) — AI 문제 해결, 기능 추가, 문서화

#### 8단계: AI 댓글 배포 환경 문제 해결
- 배포 환경에서만 AI 칭찬 댓글이 생성되지 않는 문제 발생
- 로컬에서는 정상 작동

**디버깅 과정:**
1. 에러 메시지를 사용자에게 표시하도록 클라이언트 코드 수정
2. 에러 확인: `API_KEY_INVALID` (Gemini API 키 무효)
3. Vercel 환경 변수 진단용 임시 API 엔드포인트 생성 (`/api/debug-env`)
4. 진단 결과: Vercel에 `GOOGLE_GEMINI_API_KEY`가 등록되어 있지 않음 (`hasKey: false`)
5. Vercel 환경 변수 등록을 여러 번 시도했으나 계속 실패
6. 최종 해결: `.env.production` 파일에 직접 API 키를 추가하여 커밋

**배운 점:**
- Vercel 환경 변수 설정이 예상대로 동작하지 않을 때, .env.production에 직접 추가하는 것이 확실한 방법이다.
- 디버깅 시 진단용 엔드포인트를 만들면 서버 환경을 직접 확인할 수 있어 유용하다.
- 문제 해결 후 진단 코드는 반드시 삭제한다.

#### 9단계: 갤러리 자동 학년도 관리
- 교사가 수동으로 갤러리를 생성/마감하는 방식을 제거
- 학생 글이 작성 시점의 학년도(3월~다음해 2월)에 자동 배정되도록 변경

**변경 전:**
> 교사가 "새 학년도 갤러리 생성" 버튼을 눌러야 해당 연도 갤러리가 만들어지고, "마감" 버튼으로 관리

**변경 후:**
> 갤러리 생성/마감 버튼 모두 제거. 학생이 글을 쓰면 현재 날짜 기준으로 학년도가 자동 배정됨

**사용한 프롬프트:**
> "교사용 갤러리에서 '새 학년도 갤러리 생성' 없애줘. 학생들이 작성한 글은 학년도 기준인 '3월부터 다음해 2월까지'에 따라 해당 학년도에 글이 등록되도록 해줘"

#### 10단계: 미션 기간 체크 기능
- 미션의 시작일~마감일 밖에서는 학생이 글을 작성할 수 없도록 제한
- 미션 카드에 "시작 전" / "마감" 상태 표시
- 글쓰기 페이지에서도 기간 체크 (URL 직접 접근 차단)

**사용한 프롬프트:**
> "학생이 작성한 글의 날짜가 교사가 생성한 미션 시작일과 마감일 사이가 아니면 목록만 표시되고 들어가서 글을 작성하지 못하도록 해줘"

#### 11단계: 모바일 스트림 레이아웃
- 모바일(768px 미만)에서 갤러리 레이아웃을 스트림형으로 고정
- 레이아웃 전환 버튼 자동 숨김
- PC/태블릿에서는 기존처럼 3가지 레이아웃 전환 가능

#### 12단계: 음성 입력 기능 추가 및 버그 수정
- Web Speech API를 활용한 한국어 음성 인식 기능 추가
- 관찰 내용 입력란에 "🎤 음성 입력" 버튼 배치

**겪었던 문제와 해결 과정:**

| 시도 | 방식 | 문제점 |
|------|------|--------|
| 1차 | `continuous: true` + `interimResults: true` | 같은 단어가 반복되어 추가됨 |
| 2차 | 처리된 인덱스를 추적 (`lastProcessedIndex`) | 여전히 중복 발생 |
| 3차 | 음성 시작 시점 텍스트 저장 + 전체 결과 재조합 | 더 심해짐 |
| 4차 | `continuous: false` + 자동 재시작 | 여전히 중복 |
| **최종** | **`continuous: false` + `interimResults: false`** | **정상 작동** |

**최종 해결 방식:**
- `continuous: false`: 한 문장 인식 후 자동 종료
- `interimResults: false`: 중간 결과 없이 최종 결과만 1회 반환
- `onresult`가 정확히 1번만 호출되어 중복이 구조적으로 불가능
- 연속 입력은 버튼을 다시 눌러서 시작

**추가로 발견한 문제:**
- 모바일 브라우저의 강한 캐시 때문에 코드 수정 후에도 이전 버전이 실행됨
- 시크릿 모드로 테스트하여 확인 후, 사용자에게 캐시 삭제 방법 안내

**배운 점:**
- Web Speech API의 `continuous` 모드는 브라우저마다 동작이 다르고, 결과 누적 방식이 예측하기 어렵다.
- 가장 단순한 방식(`continuous: false` + `interimResults: false`)이 가장 안정적이다.
- 모바일 테스트 시 반드시 캐시를 고려해야 한다.

## 개발 중 겪은 주요 문제와 해결

### 문제 1: Firebase 빌드 시 초기화 에러
- **상황**: Vercel 빌드 시 Firebase가 초기화되면서 환경 변수가 없어 에러 발생
- **원인**: Next.js의 정적 빌드 과정에서 모듈 로드 시 Firebase가 즉시 초기화됨
- **해결**: 직접 초기화 대신 getter 함수(`getDb()`, `getAuthInstance()`)로 지연 초기화
- **교훈**: 외부 서비스 연동 시 빌드 타임과 런타임의 차이를 고려해야 한다

### 문제 2: Vercel 환경 변수 미적용
- **상황**: Vercel 대시보드에서 환경 변수를 여러 번 등록했으나 서버에 반영되지 않음
- **원인**: Vercel 환경 변수 설정 과정에서의 문제 (정확한 원인 불명)
- **해결**: `.env.production` 파일에 직접 추가하여 소스 코드에 포함
- **교훈**: 환경 변수 설정이 실패할 때는 대안을 빠르게 찾는 것이 중요하다

### 문제 3: AI 댓글 배포 환경에서만 실패
- **상황**: 로컬에서는 AI 댓글이 정상 생성되지만, 배포 환경에서만 `API_KEY_INVALID` 에러
- **디버깅**: 진단용 API 엔드포인트를 만들어 서버의 환경 변수 상태를 직접 확인
- **해결**: 환경 변수가 없는 것을 확인하고 `.env.production`에 직접 추가
- **교훈**: 로컬과 배포 환경의 차이를 디버깅할 때는 진단 도구를 만들어 활용하면 효과적이다

### 문제 4: 음성 입력 단어 반복
- **상황**: Web Speech API `continuous` 모드에서 같은 단어가 계속 반복되어 입력됨
- **원인**: `onresult` 이벤트의 결과 누적 방식이 브라우저마다 다름
- **시도**: 인덱스 추적, 전체 재조합 등 4가지 방식 시도 → 모두 실패
- **해결**: `continuous: false` + `interimResults: false`로 가장 단순한 방식 채택
- **교훈**: 복잡한 해결책보다 단순한 해결책이 더 안정적일 수 있다

### 문제 5: 모바일 캐시
- **상황**: 코드를 수정하고 배포했는데 모바일에서 이전 버전이 계속 실행됨
- **원인**: 모바일 브라우저의 공격적인 캐시 정책
- **해결**: 시크릿 모드로 테스트하여 코드 문제와 캐시 문제를 구분
- **교훈**: 모바일 테스트 시 반드시 캐시를 초기화하거나 시크릿 모드를 사용해야 한다

## 바이브코딩 활용 방법

### AI와의 협업 방식

본 프로젝트는 Claude Code를 활용한 바이브코딩으로 개발되었다. 개발자가 자연어로 요구사항을 설명하면, AI가 코드를 작성하고, 개발자가 테스트하고 피드백하는 방식으로 진행했다.

```
[개발자] 요구사항 설명 (자연어)
    ↓
[AI] 코드 작성 + 빌드 확인
    ↓
[개발자] 테스트 및 피드백
    ↓
[AI] 수정 및 개선
    ↓
(반복)
```

### AI가 잘하는 것

| 영역 | 예시 |
|------|------|
| 초기 구조 설계 | 프로젝트 폴더 구조, 타입 정의, CRUD 함수 생성 |
| 반복적인 코드 작성 | 비슷한 패턴의 페이지, 컴포넌트 일괄 생성 |
| 에러 분석 | 빌드 에러 메시지 분석 및 수정 방안 제시 |
| 리팩토링 | 기존 코드를 새로운 요구사항에 맞게 수정 |
| 문서화 | 코드 기반 사용 설명서, 기획안 작성 |

### 개발자가 해야 하는 것

| 영역 | 예시 |
|------|------|
| 요구사항 정의 | "어떤 앱을 만들 것인가" 명확히 설명 |
| 테스트 | 실제 브라우저/모바일에서 기능 확인 |
| 피드백 | "이 부분이 안 된다", "이렇게 바꿔달라" 구체적 전달 |
| 환경 설정 | Firebase 프로젝트 생성, Vercel 연동, API 키 발급 |
| 디자인 판단 | UX 흐름, 색상, 레이아웃 등 사용자 경험 결정 |

### 효과적인 프롬프트 작성법

**좋은 프롬프트:**
> "학생이 작성한 글의 날짜가 교사가 생성한 미션 시작일과 마감일 사이가 아니면 목록만 표시되고 들어가서 글을 작성하지 못하도록 해줘"

→ 조건(미션 기간 밖), 동작(목록만 표시), 제한(글 작성 불가)이 명확하다.

**개선이 필요한 프롬프트:**
> "미션 기능 좀 고쳐줘"

→ 무엇을 어떻게 고칠지 불분명하다.
